# 多岗位求简历与接收核心

本版本按用户要求仅提炼代码、做本地行为验证，不进行真实简历操作。核心来源为既有运维回收脚本，不运行原脚本，也不继承其中 ops-growth 正则、2026-09-20 时间、offset 或旧浏览器守卫。

## 同一套代码怎样换岗位

`boss_config.mjs` 装入任意岗位集合；`boss_chat.mjs` 负责页面；`boss_resumes.mjs` 负责统一判断、去重、预算、批次和完成状态。目标必须同时符合岗位 ID、配置标题和范围，不能因为名字含“运维”或“增长”就处理。

三种范围：

- `all_history`：授权岗位的全部历史，必须有用户本次明确授权。
- `since`：某时间之后更新的授权岗位会话，可能包含历史会话；不能说它等于本轮新招呼。
- `conversation_allowlist`：稳定会话编号的 SHA256 白名单，严格限定具体会话。它与推荐卡片的 encrypted geek 指纹不是同一种编号，不能混用或靠姓名转换。

## 求简历

先加载完整列表，再按稳定 ID 冻结本轮范围，逐会话核对当前对象与岗位并加载完整聊天记录。打开未读会话会标记已读，因此真实检查也需在当前用户范围内。

明确勿扰信号跳过并交人工；待同意附件、已收到附件/明确在线简历、已请求过、历史未决、按钮不可用分别记录。不可用不算失败，不发额外快捷回复来激活按钮。

缺少“求简历”按钮或附件卡片形态不符合已知结构时转待复核，不能把“未识别”算成“没有待处理”。存在未复核卡片时，不报告全范围剩余为零。

其余才点“求简历”，核对平台默认确认内容，确认瞬间再核对会话与岗位，先写意图再点“确定”。必须出现请求状态或明确请求消息并关闭确认框；只有按钮变灰不确认成功。超时或证据缺失停写、隔离，不补点。

去重以会话指纹为键，共用追加事件；可以读取明确配置的旧简历日志。预算限制真实请求数，未处理的合格请求记延期，阶段为 partial。完整检查完成并不意味着每位人选都能求简历。

## 接收附件简历

从聊天全文中找明确“对方想发送附件简历给您，您是否同意”的仍可操作卡片，按稳定消息 ID 点“同意”。不处理换电话、微信、拒绝、面试或购买；不靠列表最后一条消息判断是否有附件。

点击前核对会话、岗位和具体消息 ID；同意后必须同时看到该待处理卡片结束与同一会话新增附件证据。卡片单独消失不算回收成功。去重键为会话指纹＋消息指纹，未知记录不自动过期。

处理后从列表顶部再完整复查。只有完整一轮无待同意附件、无未决记录、无确认框才标完成，并记录复查截止。预算用尽或复查轮数用尽标 partial，不填“剩余 0”。这是 BOSS 中接收，不会下载 PDF、导入飞书或评估简历。

## 为什么不用 offset

发送和收到新消息会改变列表排序；offset=325 不保证还是原来的第 326 位。新控制器按已核验的稳定会话集合推进，批次只控制检查/写入节奏，不当作业务范围。列表加载未到底则停，不沿用截图里的子批次 complete 作为全范围结果。

## 未验证的部分

真实 DOM 与 Vue 字段、平台当前默认确认框、界面状态更新时序和附件语义仍需未来获授权后做小范围验证。本地模拟测试能证明控制器的边界和多岗位配置复用，不能证明平台本次真的接收了简历。
