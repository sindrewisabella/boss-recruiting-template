# 通用打招呼阶段

使用 schemaVersion=2 的配置，由 `profiles` 提供任意数量的岗位和各自规则。发送端不写死增长、运维、两个岗位或同一句话术；同名岗位必须按 ID 分开。

统一入口：

```bash
./boss.command run --authorization /本轮私有目录/run.json --execute
```

单阶段可令 `actions: ["greet"]`。兼容的独立入口为 `greet --authorization 文件 --execute`，也要当前授权。旧 schemaVersion=1 文件不再作为执行配置，历史对账使用 `reconcile`。

开轮核对账号和每个实际岗位 ID 对应的已保存话术。缺少专用话术或与配置不符时停；不擅自写入设置。先做独立 1 条实际话术试验，再批量；批量配置的 `firstGreetingVerified` 必须有实际读回依据，不能仅凭设置页勾选。

开始查官方剩余；逐批仅按关联回执扣减，结束查官方新增。候选卡片每次重新读，执行该岗位的画像；学历字段只表示卡片实际提供的最高学历，不等于第一学历。点击瞬间再次核对 ID、岗位和职业/基础文本变化。

先落发送意图，正常 UI 点击，关联自然产生的人选/岗位请求与响应。当前严格回执合同为 HTTP200、code=0、status=1、newfriend=1 且无阻断或引导；属于观察到的私有实现，平台变化需要重新验证。未点击且事实变化时停写，不把它算未知发送；点击后无关联回执则持久隔离，不重发。

结束时官方差值不符、存在未知或目标未达，不能标 `complete`。最终剩余重算，避免残留最后批次前的值。权益显示口径变化时仅保存原始值，不强行算差。

新通用版本做了本地验证；此前新增 94 条来自旧版增长实测，不代表新版全部岗位已经实测。
